# Working agreements

- Read `docs/PROJECT_CONTEXT.md` first, every session.
- After EVERY completed task, before your final report, update `docs/PROJECT_CONTEXT.md` without asking: status, changelog line, any new decision, new known issues, changed commands or structure. Also update Roles/Storage/Business rules if they changed.
- Never write secrets, passwords, tokens, keys or customer data into it; mention environment variable names only.
- Keep it under ~400 lines: condense old changelog entries instead of growing the file.
- If code and the file disagree, trust the code and correct the file.
- Updating this file is always allowed; all other changes follow the owner's usual approval rules.
